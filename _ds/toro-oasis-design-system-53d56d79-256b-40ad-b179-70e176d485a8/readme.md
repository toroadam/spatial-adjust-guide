# Toro Oasis Design System

Source of truth for **Toro's Oasis platform** — the shared UI system behind Toro's connected irrigation and outdoor-equipment products (Oasis web console, the SMRTscape Pulse iOS app, and related surfaces like iCentral and Lynx Drive). Built from a component library, not from public convention — every value here traces back to the attached Figma file or codebase, not to a public design-library default.

**Sources**
- Figma file: `Oasis_Design_System.fig` (mounted read-only; internally titled "TORO SMRTscape x Blink Component Library" — see `/Cover`). 19 pages, ~47,800 nodes, 1,921 component families, 67 Figma Variables across 6 collections, 0 named text styles (type is set ad hoc per instance, not via shared styles).
- Codebase: `SMRTScapeiOS/` — SwiftUI iOS app ("SMRTscape Pulse") for BLE controller provisioning, alerts, and map-based device management. Its `styleguide/` Swift package is the native counterpart to this web/React system.
- Fonts: `uploads/golos-ui_regular.ttf`, `_medium.ttf`, `_bold.ttf` — the real Golos UI files, not a substitute.

## Products in scope
- **Oasis Web Console** — contractor/owner dashboard: client lists, controller diagnostics, zone scheduling, alerts, reports.
- **SMRTscape Pulse (iOS)** — homeowner + contractor mobile app: BLE provisioning, map view, zone control, alerts.
- Frame names in the source (`ContractorTabBar`, `HomeownerTabBar`, `OwnerTabBar`, `Console`, `Client Profile`) indicate three user roles sharing one component system: **Contractor**, **Homeowner/Owner**, and internal **Support/Console**.

## Scope decisions (read before extending)
The Figma file's "Component families" count (1,921) is dominated by a generic Fluent-style icon library on the `/Iconography` page (~1,700+ individual glyph families — Add, Arrow, Airplane, etc.) that is not Toro-specific. This system:
1. Built all **148 real UI components** in `components/oasis/` — every named component from Buttons, Form-Fields, Dropdown-Menus, Navigation, Table-Rows, Map-Pins, Tooltips-Popovers-Toasts, Details-Panel, Toolbar, and the standalone symbols list.
2. Built **381 generic Fluent icon glyphs** in `components/icons-fluent/` — the full alphabetical A–Column range enumerable from the .fig's directory listing (the tool used to browse the .fig caps list output; letters past "Column" weren't enumerable in this pass).
3. Left the remaining ~1,390 generic Fluent icon families (roughly D–Z) un-built. Each is a single-glyph component with no Toro-specific design decisions in it — pull any one on demand from `/Iconography/<Name>` in the .fig.

Total built: **529 of 1,921 families**. This is an intentional, documented scope call given the source's scale — not an oversight.

## Visual foundations
- **Type**: Golos UI only (Regular 400 / Medium 500 / Bold 700). It's "uniwidth" (line length is identical across weights) and its numerals are monospaced — built for dense tables and schedules. No named text styles exist in the file; sizes are set per-instance: 10, 12, 14, 16, 18, 24, 32, 40, 48px. Buttons and tags use Bold, uppercase, +0.5–2px tracking. Headings use Bold with tight (−1px) tracking at large sizes. Body copy is Regular, no tracking.
- **Color**: Neutral grayscale ramp (White → 05 → 10…90 → 100, i.e. `#FFFFFF` → `#080D12`) carries almost all UI. **Toro Red** (`#E11837`, tint `#FA5069`, shade `#C91E38`) is the only brand hue and appears sparingly — CTAs, brand marks, destructive emphasis is otherwise handled by the semantic Negative ramp, not red. Semantic ramps (Positive/Warning/Negative/Informative, 3 steps each: light→base→dark) drive status, alerts, and form validation. A 13-color "Zone" palette (Willow, Dandelion, Forest, Slate, Sienna, Holly, Sand, Sage, Peach, Caramel, Brass, Lavender, Periwinkle) colors map pins and schedule zones so multiple zones stay visually distinct.
- **Spacing**: 8px base unit; 4px allowed for small elements. Scale: 4, 8, 12, 16, 20, 24, 32, 40, 48, 72, 128, 192.
- **Radius**: 8px default (buttons, cards, inputs), 4px on compact/small buttons, pill (999px) on tags and toggles.
- **Shadows/borders**: mostly flat with 1px inset borders (`inset 0 0 0 1px var(--20|--30)`) rather than drop shadows — Secondary buttons and inputs use an inset stroke, not a shadow, to read as "outlined." Focus state is a 2px outer ring in Informative Blue (`rgb(48,121,240)`, or the lighter `rgb(102,161,255)` on dark backgrounds) — never a color swap alone. The few real shadows (`--shadow-sm`, `--shadow-md`) are soft and dark-neutral (`rgba(8,13,18,…)`), used under floating surfaces like tooltips/popovers/modals, not resting cards.
- **Backgrounds**: flat neutral fills; no gradients, no patterns, no illustration-style backgrounds. The map surface (Mapbox in the real app) is the only "photographic" background — pins and clusters sit on top of it.
- **Buttons/press states**: Primary = filled Neutral-90/Red; Secondary = 1px inset outline; Minimal = text-only, colored link-blue. Hover darkens/lightens the fill by one neutral step; disabled drops to muted gray text on Neutral-90 (dark) or gray-on-gray (light); there is no scale/shrink press animation observed — state changes are color/fill only.
- **Icons**: single-color glyphs that inherit `currentColor` — no multi-color icon treatment. Sized 12/16/20/24/28/48px in Regular or Filled "theme."
- **Imagery**: no photography or illustration in the kit itself beyond one avatar bitmap and a couple of documentation screenshots (extracted into `components/oasis/assets/`). The product's real imagery is user avatars and the live map — there is no stock/hero photography style to match.
- **Animation**: two named animated components exist in the source (`Alert-animation`, `Watering-animation`) — multi-frame sprite-style state changes (e.g. an alert pulsing, a sprinkler animating) rather than eased transitions; no easing curves or bounce values are specified in the file.
- **Transparency/blur**: none observed — no glass/blur surfaces in the kit.
- **Layout**: dense, data-forward — table rows, list items, and dashboard cards are the dominant pattern; the Web console uses a persistent global header + tab/nav pattern, the mobile app uses a bottom tab bar (role-specific: Owner/Homeowner/Contractor).

## Iconography
Icon language is Microsoft's Fluent-style outline/filled icon set (evident from the `/Iconography` page's glyph names and Size/Theme variant structure), used generically rather than as a custom Toro icon font. No emoji, no unicode-glyph icons, and no built-in icon font are used in the product — icons are individual vector components, single-color, recolored via `currentColor`. This system ships the ~45 glyphs actually referenced by the 148 built components (see list above); the remaining ~1,700 Fluent glyphs in the source file are not pre-built but can be pulled from `/Iconography/<Name>` on request.

## Content fundamentals
- **Tone**: plain, operational, factual — status and instructions, not marketing voice. "Watering was completed as programed - A.", "Controller offline since 11:20 AM", "36/41 controllers online."
- **Voice**: mostly systems reporting state (third person / passive: "Program B Added") rather than direct address; where the UI does speak to the user it's plain imperative on buttons ("Save Program", "Cancel").
- **Casing**: Title Case for nav/section labels and card titles ("Watering Schedule", "Client Profile"); Sentence case for body/help text; UPPERCASE with letter-spacing for button labels only.
- **Numbers**: real counts and units drive the UI ("36/41", "14 urgent", "53° F", "10%") — the font's monospaced numerals exist specifically to keep these aligned in tables.
- **No emoji** anywhere in the kit.
